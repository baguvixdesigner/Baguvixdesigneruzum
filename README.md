# Uzum × Taobao/1688 Trend Bot

Telegram-бот поиска товарных ниш: пересечение трендов на Taobao/1688 со свободными
(ещё не занятыми) нишами на Uzum Market. Полное ТЗ — см. документ, приложенный к задаче.

Стек: TypeScript, Node.js, [Telegraf](https://telegraf.js.org/), Prisma + PostgreSQL.

## 1. Архитектура

```
prisma/schema.prisma     — все модели из ТЗ (Category, ProductSnapshot, TelegramUser, кошелёк и т.д.)
src/config/env.ts        — загрузка и валидация переменных окружения
src/db/prisma.ts         — синглтон Prisma Client
src/services/
  exchangeRate.ts         — курс CNY→UZS с фида ЦБ РУз, кэш (CACHE_TTL_HOURS)
  oxylabs.ts               — клиент Oxylabs E-Commerce Scraper API (Taobao + 1688)
  uzum.ts                   — поиск совпадений через graphql.umarket.uz (+ резерв Apify)
  translate.ts               — перевод названий товаров на русский
  pipeline.ts                 — полный пайплайн сбора по категории (раздел 5 ТЗ)
  search.ts                    — выдача закэшированных товаров пользователю постранично
  wallet.ts                     — баланс, списания, заявки на пополнение
  categories.ts                  — список категорий v1 (раздел 3 ТЗ)
src/i18n/                  — словари фраз RU/UZ + t() хелпер
src/bot/                    — Telegraf-бот: клавиатуры, сессии, хендлеры (флоу раздела 6 ТЗ)
scripts/seed.ts              — засевает категории v1 в БД
```

## 2. Локальный запуск

```bash
npm install
cp .env.example .env        # заполнить BOT_TOKEN, ADMIN_TELEGRAM_ID, ключи Oxylabs и т.д.
docker compose up -d        # поднимает PostgreSQL локально
npm run prisma:migrate      # создаёт таблицы
npm run seed                # засевает категории v1
npm run dev                 # запускает бота (tsx watch)
```

Для продакшн-сборки: `npm run build && npm run start` (перед этим `npm run prisma:deploy`
вместо `prisma:migrate`).

## 3. Переменные окружения

См. `.env.example` — там же комментарии по каждой. Ключевые:

- `BOT_TOKEN` — токен бота от @BotFather.
- `ADMIN_TELEGRAM_ID` — telegram_id Карима (получает заявки на пополнение и предложенные категории, единственный, кому доступны админ-действия внутри бота).
- `OXYLABS_USERNAME` / `OXYLABS_PASSWORD` — единая подписка Oxylabs E-Commerce Scraper API (покрывает и Taobao, и 1688).
- `TOPUP_CARD_NUMBER` / `TOPUP_CARD_HOLDER` — реквизиты, которые бот показывает при пополнении.
- `QUERY_PRICE_SUM` (14 900), `MIN_TOPUP_SUM` (50 000), `CACHE_TTL_HOURS` (24) — бизнес-константы из ТЗ, вынесены в конфиг, чтобы менять без правки кода.

## 4. Что уже реализовано (по этапам ТЗ, раздел 9)

1. ✅ Схема БД — все модели раздела 4 ТЗ, плюс служебное поле `rank` на `ProductSnapshot` для сохранения порядка ранжирования пайплайна между запросами (Prisma сам не гарантирует порядок без явного `ORDER BY`).
2. ✅ Курс валют — `exchangeRate.ts`, фид ЦБ РУз, кэш в таблице `ExchangeRate`.
3. ✅ Пайплайн сбора — `pipeline.ts`: Oxylabs (Taobao+1688 всегда вместе) → перевод → поиск на Uzum → `noveltyLabel` → ранжирование → топ-40 в `ProductSnapshot`.
4. ✅ Бот: главное меню, группа → подкатегория → источник → выдача, «Ещё 10», «Предложить категорию» — `src/bot/handlers/search.ts`, `mainMenu.ts`, `start.ts`.
5. ✅ Кошелёк — баланс, флоу пополнения карта/скриншот/подтверждение админом — `wallet.ts` (сервис) + `bot/handlers/wallet.ts`.
6. ✅ Мультиязычность — `src/i18n`, переключатель в главном меню, весь текстовый слой бота — только через словарь ключей.
7. ✅ Админ-функции внутри бота — подтверждение/отклонение пополнений и предложенных категорий, доступ только по `ADMIN_TELEGRAM_ID` — `bot/handlers/admin.ts`.
8. ⏳ Деплой на VDS — см. раздел 6 ниже, скрипты и docker-compose для БД готовы, процесс-менеджер (pm2/systemd) — на усмотрение при деплое.

## 5. Что сознательно оставлено как гипотеза / требует проверки перед продакшеном

Согласно разделу ТЗ «Следующий шаг» — эти три пункта не блокируют разработку, но
**обязательны перед оплатой подписки Oxylabs и запуском на реальных пользователях**:

1. **Формат ответа Oxylabs.** В `src/services/oxylabs.ts` источники захардкожены как
   `taobao_search` / `1688_search` (переопределяются через `OXYLABS_SOURCE_TAOBAO` /
   `OXYLABS_SOURCE_1688`), а парсинг полей (`title`, `price`, `sales`, `url`...) — рабочая
   гипотеза. Нужно прогнать бесплатный пробный доступ (2000 результатов) и свериться с
   реальной структурой JSON, при необходимости — поправить `parseOxylabsResults`.
2. **Свежесть данных Oxylabs.** Уточнить у их поддержки — живой скрейпинг на каждый запрос
   или есть внутреннее кэширование, — чтобы понимать реальную свежесть поверх нашего TTL 24ч.
3. **Схема GraphQL Uzum.** Запрос `SearchProducts` в `src/services/uzum.ts` основан на схеме
   community-проектов, а не официальной документации (её не существует — раздел 5.1 ТЗ).
   Домены `graphql.umarket.uz` / `api.umarket.uz` из исходного ТЗ **больше не резолвятся**
   (проверено DNS-запросом с реального VDS, не только из песочницы) — похоже, устарели.
   Актуальный бренд-домен подтверждён вручную (`scripts/discover-uzum-api.ts`):
   `graphql.uzum.uz` резолвится и отвечает HTTP 401 (эндпоинт жив, не хватает заголовков),
   `api.uzum.uz` — HTTP 403. Конфиг (`env.ts`, `.env.example`) и `uzum.ts` уже переключены
   на новый домен, добавлен заголовок `X-Iid` (без него — 401). Но точный набор нужных
   заголовков/токенов и реальная структура ответа `makeSearch` — ещё не подтверждены,
   нужно прогнать `scripts/prototype-uzum.ts` (пробует несколько наборов заголовков и
   вариантов схемы) и/или открыть uzum.uz в браузере с DevTools → Network и посмотреть
   реальный запрос поиска. При расхождении — правится только `src/services/uzum.ts`,
   архитектура пайплайна не меняется.
4. **Пороги `noveltyLabel`.** В `pipeline.ts` (`NOVELTY_THRESHOLDS`) — заглушка
   (🟢 ≤ 50 заказов, 🟡 ≤ 500, 🔴 выше). Согласно ТЗ, точные пороги подбираются на реальных
   данных при разработке — поменять одну константу после первых прогонов.
5. **Китайские поисковые запросы** в `src/services/categories.ts` (`chinaSearchTerms`) —
   первая версия ключевых слов на китайском для каждой подкатегории. Стоит свериться с
   реальной выдачей Oxylabs и при необходимости расширить/уточнить список на категорию.
6. **Перевод названий.** По умолчанию используется неофициальный Google Translate endpoint
   без ключа (`TRANSLATE_PROVIDER=google-unofficial`) — у него неявные лимиты. Для продакшн-
   нагрузки переключить на `TRANSLATE_PROVIDER=yandex` с `YANDEX_TRANSLATE_API_KEY`.
7. **Сессии бота** сейчас в памяти процесса (`telegraf` in-memory session store) — подходит
   для одного процесса на VDS. При масштабировании на несколько инстансов — заменить на
   Redis-backed session store.

## 6. Деплой на VDS

1. Склонировать репозиторий на сервер, `npm ci`, `npm run build`.
2. Поднять PostgreSQL (см. `docker-compose.yml` как образец, либо использовать существующий на VDS, как в других проектах — Terracotta/шаблон Instagram-магазинов).
3. Заполнить `.env` на сервере (реальный `BOT_TOKEN`, ключи Oxylabs, реквизиты карты).
4. `npm run prisma:deploy && npm run seed`.
5. Запустить `node dist/index.js` под процесс-менеджером (pm2/systemd), чтобы бот
   переживал рестарты сервера.
6. Протестировать на 2-3 категориях перед полным включением остальных (`Category.active`
   можно переключать прямо через админ-функции бота, когда они понадобятся, или напрямую в БД
   для первого теста).
